# SDD для Forma Prime

Эта папка хранит рабочий слой проекта: метод, контекст, спеки, решения и материалы для ревью. Код остается в `src`, база в `prisma`, тесты в `tests`; здесь фиксируется, почему и как мы меняем продукт.

## Как работать

1. Перед изменением создаем или обновляем spec в `specs/`.
2. В spec описываем цель, пользовательский сценарий, границы, данные, риски и проверку.
3. Если появляется архитектурное решение, фиксируем его в `decisions/`.
4. После реализации собираем review-pack в `reviews/`, если задачу нужно разбирать или передавать напарнику.
5. В `backlog.md` держим идеи, улучшения и технические долги, которые пока не стали spec.

## Минимальный цикл

```text
idea -> spec -> implementation -> tests -> review -> decision/backlog update
```

## Где что лежит

- `method.md` - правила SDD для этого проекта.
- `project-context.md` - текущий контекст продукта и технической базы.
- `backlog.md` - список будущих задач и наблюдений.
- `specs/` - конкретные продуктовые и технические спецификации.
- `decisions/` - принятые решения с причиной и последствиями.
- `reviews/` - review-pack'и, аудиты и разборы готовой работы.

## Именование

Используем короткие номера и понятные названия:

```text
specs/001-onboarding-polish.md
decisions/001-food-resolution-strategy.md
reviews/2026-06-26-current-state.md
```
