# Reviews

Здесь лежат review-pack'и, аудиты и разборы уже сделанной работы.

## Когда создавать review-pack

- Изменение затрагивает несколько модулей.
- Нужно передать контекст напарнику.
- Нужно сравнить реализацию со spec.
- Нужно сохранить материал для будущего анализа метода.

## Шаблон

```markdown
# Review: Название

## Дата

YYYY-MM-DD

## Объем

Какие файлы, сценарии и spec смотрим.

## Что изменилось

Кратко по факту.

## Проверка

- Тесты:
- Сборка:
- Ручные сценарии:

## Наблюдения

- Риски:
- Долги:
- Идеи:

## Следующие шаги

Что стоит сделать дальше.
```
